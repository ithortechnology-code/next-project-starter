# Auth example web surface

## Mode
Operate. A contributor's end user must complete the email/password auth lifecycle on desktop and mobile web.

## Product truth
Generic, forkable Project Starter example. Do not add product-specific business features or claims. The auth flow includes sign-up, email verification and resend, sign-in, forgot/reset password, protected session, sign-out, rolling server-validated sessions, and revocation on sign-out/reset.

## Direction contract
Use the user's Razorpay account sign-in/sign-up references for the auth-page composition cues: a polished two-panel frame, a confident blue-led accent, clear welcome and task headings, generous whitespace, restrained form controls, and one obvious primary action. Adapt those cues into the generic Project Starter identity. Do not reproduce Razorpay marks, marketing claims, country/company fields, social sign-in, or legal copy. Keep the form's labels, links, and states specific to the starter's email/password lifecycle.

## Surface concept
The form is the task; an adjacent quiet explainer helps contributors understand the lifecycle. At mobile widths, retain the task heading and form as the first reading path and collapse the explainer without obscuring controls.

## Responsive constraints
Web desktop and mobile web; support 320px width and larger, keyboard and screen reader use, reduced motion, visible focus, inline errors, and status feedback.
